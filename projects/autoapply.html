The guardrails are the product

AutoApply searches job sources, scores fit with a breakdown you can argue with, and writes tailored application documents from a verified pool of facts. Nothing reaches an employer without a human approving it.

7 pipeline stages 1,000+ document versions tracked Human gate before every submit Local LLM, no per-token bill
01The problem

It started as a script and the script was wrong

The first version filled forms. That is the version everybody builds, and it fails for a reason that has nothing to do with automation quality: a language model writing your resume will invent achievements. Not maliciously. It fills a gap because the prompt asked for a compelling bullet and a compelling bullet was not available.

Sending that to an employer under your own name is the actual risk in this product. Everything interesting in the build is a response to it.

02The gate

A queue you have to walk through

Prepared applications land in a review board and stop there. Approve, skip, or bulk-skip everything matching a pattern. There is no autopilot setting, because the whole argument of the system is that the last call is a person's.

Each card carries the posting link and the generated documents, so approving is an informed act rather than a reflex. "I applied manually" exists because half the time the right move is to go do it yourself, and the system should record that instead of pretending it did the work.

03Fact grounding

The model does not get to make things up

Document generation reads from a verified pool of claims rather than from free imagination. Every bullet traces to something in the pool. A drift check runs over the finished document and flags any assertion that did not come from there.

Scoring works the same way. Instead of a single opaque number, each match decomposes into weighted factors with the evidence attached, so a low score is a readable argument rather than a verdict. When the system says a role is a 0.74, you can see that it scored 0.30 on fintech background and decide whether you agree.

That funnel is the honest picture of what this kind of system is for. Volume in, ruthless narrowing, small number of considered applications out. A tool that submitted all 1,284 would be worse than useless.

04Under the hood

Where the complexity actually lives

  • Deduplication across sources. The same role appears on three boards with three different titles. Collapsing those correctly is unglamorous and it is most of what makes the pipeline usable.
  • A version ledger. Over a thousand generated documents, each tied to the job, the profile and the template that produced it. Without that, debugging a bad generation is guesswork.
  • Async where it matters. Celery workers over Redis handle the long jobs so the interface never blocks on a model call, and cached responses keep repeat scoring cheap.
  • Explainable by construction. The score breakdown is not a post-hoc explanation of a black box. It is how the score is computed.
