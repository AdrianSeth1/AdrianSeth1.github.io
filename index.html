AI product operations · Research system

Verity — BTC evidence lab paper only

A local research lab that streams Coinbase and read-only Kalshi data, compares a settlement model with market prices, journals every decision, and returns no-trade when the evidence is weak. There is no order-entry method and no real-money execution.

60-second walkthrough

read time · about 60 sec
  1. 01Set the boundaryCoinbase supplies public market data; Kalshi access is read-only. The product observes and records. It cannot place an order.
  2. 02Compare the evidenceA settlement-aware estimate sits beside the same-snapshot market midpoint, with source quality, timing, and uncertainty kept visible.
  3. 03Gate the decisionMissing evidence, weak expected edge, or unreliable timing produces no-trade. Signals and rejected decisions remain in an audit ledger.
  4. 04Test the storyThe comparison view currently says the market baseline is stronger. That is the useful result: reject the exciting claim and keep execution disabled.

I owned

Problem framing, source and settlement-rule research, product requirements, acceptance criteria, evaluation gates, UI priorities, and the go / no-go decisions.

AI implemented

Coding agents generated substantial parts of the code, tests, and documentation from my plans, then revised the system through iterative feedback.

Evidence bar

Paper-only operation, read-only data access, causal timing checks, journaled decisions, explicit rejection gates, and conclusions that can say “not proven.”

How I work: I use AI coding agents as the implementation layer. My value is deciding what to build, translating research into precise constraints, and refusing to call the result successful until the evidence supports it.

03
AI · Full-stack platform

AutoApply — job-search automation platform

What started as "a script to fill forms" became a multi-service platform: a Vue 3 SPA over a FastAPI backend, PostgreSQL, Redis/Celery workers, and local LLMs — searching job sources, scoring fit with explainable rules, and generating tailored, fact-checked application documents.

Under the hood
The interesting engineering is in the guardrails: document generation is evidence-grounded (bullets come from a verified pool with fact-drift validation, so the LLM can't invent achievements), every submission is gated behind a human review queue, and scoring produces an explainable breakdown instead of a black-box number. Caching, deduplication across job sources, and a version ledger keep a 1,000+ document pipeline auditable.

04
AI · Developer tools

Apoapsis Harness — verification layer for coding agents

An experiment in splitting coding-agent work between local and hosted models: local models handle routine search, edits, and checks; harder planning escalates with only the context it needs — and the system knows when to stop for a person.

Under the hood
Task state, git worktrees, context retrieval, and a full audit trail live in SQLite + Git, so agent work happens in a bounded sandbox where it can't damage the main tree. In my testing it matches or beats an unharnessed local model while staying cheaper than sending everything to a frontier model — a concrete way to test routing ideas instead of arguing about them in the abstract.
